# 月次更新プロトコル

月次の自動セッションはこの手順に従う。

## 1. 準備
- `main` の最新を取得し、作業ブランチ `monthly/YYYY-MM` を作成
- `notes/` 全体と前月の `reports/` を読み、現在の方針と未解決事項を把握

## 2. 新着情報の収集（対象期間：前回レポート以降）
- `monitoring/sources.md` の各ソースについて WebSearch で確認
- 収集対象：ガイドライン改訂、第 III 相試験の主要結果、日本での承認・効能追加・保険適用の変更、安全性情報
- 各項目に **出典 URL・発表日・試験名・PMID/DOI（判明分）** を必ず付記。確認できない情報は記載しない（推測で補わない）

## 3. ノートとの照合
各新着情報について判定：
- **方針変更の提案**：現在の「方針」と矛盾、または新たな選択肢が標準化
- **根拠の更新のみ**：方針は変えず、GL 版数や根拠を差し替え
- **注視**：結果は出たが承認前・GL 未反映など（ノートには「注視」として記載）
- **影響なし**：レポートにのみ記載

## 4. 成果物
1. `reports/YYYY-MM.md` を作成：
   - 今月の要点（3 行以内）
   - ガイドライン改訂一覧
   - 重要論文・試験（疾患別、臨床的インパクト 高/中/低）
   - 日本の承認・保険関連
   - ノート修正提案の一覧（ファイル・セクション・理由）
   - 次月以降に注視する事項
2. `notes/` の該当箇所を修正：
   - 「方針」は書き換えない。提案は該当セクションの `> [!CAUTION]` ブロック（見出し「**Claude 提案（YYYY-MM）**」）に、根拠の論文・ガイドラインへのリンク付きで書く
   - 「GL」「根拠」「保険適用」は事実ベースで更新
   - 各ノートの改訂履歴と `CHANGELOG.md` に追記
3. コミット → push → `main` 向けの Pull Request を作成。PR 本文に「今月の要点」と修正提案一覧を記載
4. 変更が全くない月もレポートは作成し PR を出す（「該当なし」と明記）

## 5. 禁止事項
- 出典のない記述、記憶だけに基づく記述
- `main` への直接 push、PR の自己マージ
- 「方針」を確認なしに確定させること（提案に留める）
